# Proposal: Fix `--version`/`-V`

**Date:** 2026-08-24
**Related:** [17-homebrew-packaging.md](17-homebrew-packaging.md) — found while verifying the new
Homebrew tap end-to-end (`setdown --version` was the natural smoke test after `brew install`).

**Decision:** fix `--version`/`-V` to print an actual version string, by giving `cmdargs`'
`summary` field a version-shaped value and moving the current descriptive paragraph to `details`.

---

## Problem

```shell
$ setdown --version
setdown evaluates a .setdown definitions file to perform set operations (intersection,
difference) on line-based text files, writing one result file per definition to an output
directory.
$ echo $?
0
```

`--version` (and its short form `-V`) exits `0` and prints text, but the text is the tool's
one-paragraph description, not a version number. There is no way to ask an installed `setdown`
binary what version it is — which is exactly the kind of check a user (or a bug report, or a
Homebrew formula's own future troubleshooting steps) reaches for after installing via any of the
three channels in the README (`nix-shell`, Hackage/`stack`, or the new
[Homebrew tap](17-homebrew-packaging.md)).

## Root cause

`app/Main.hs`'s `cmdargs` mode declaration:

```haskell
options = Options
   { ...
   }
   &= program "setdown"
   &= summary "setdown evaluates a .setdown definitions file to perform set operations
              (intersection, union, difference) on line-based text files, writing one result
              file per definition to an output directory."
```

In `System.Console.CmdArgs`, `summary` is dual-purpose: it's both the banner printed at the top of
`--help` *and* the exact string printed for `--version`/`-V` — there is no separate
version-specific field. The convention in other `cmdargs`-based tools is a short banner like
`"myprogram v1.2, (C) Author"`, with a longer description (if wanted) supplied separately via
`&= details [...]`. setdown instead put its full description into `summary`, so `--version`
faithfully prints exactly what was asked of it — a description, not a version.

This has presumably been broken since the CLI was first written; it isn't a regression from any
recent change.

## Recommended approach

1. **Pull the version from Cabal, not a hardcoded string**, so it can't drift from
   `setdown.cabal`'s `version:` field the way the `v0.2.1.0` git tag already has (see
   [17](17-homebrew-packaging.md)). Cabal's `Simple` build type auto-generates a `Paths_setdown`
   module exposing `version :: Version`; `Data.Version.showVersion` turns that into `"0.2.1.0"`.

2. **Split `summary` (short, version-bearing) from `details` (long description)**:

   ```haskell
   import Data.Version (showVersion)
   import Paths_setdown (version)

   options = Options
      { ...
      }
      &= program "setdown"
      &= summary ("setdown " ++ showVersion version)
      &= details
         [ "setdown evaluates a .setdown definitions file to perform set operations"
         , "(intersection, union, difference) on line-based text files, writing one"
         , "result file per definition to an output directory."
         ]
   ```

   `details` renders as an expanded description in `--help` output (after the flag list); `summary`
   becomes the one-line `--version` banner. This keeps `--help` at least as informative as today,
   while making `--version` actually answer the question it's named for.

3. **Add `Paths_setdown` to `other-modules`** in the `executable setdown` stanza of
   `setdown.cabal`, for `cabal-version: >=1.10` builds where autogenerated modules should be
   declared explicitly rather than relied on implicitly.

4. **Add a golden/unit test** asserting `setdown --version` (or `-V`) produces output matching
   `^setdown \d+\.\d+\.\d+\.\d+$` (PVP-style four-part version) or at minimum contains the
   `setdown.cabal` version string — so this can't silently regress back to printing the
   description again.

## Concrete work items

| Item | Notes |
|---|---|
| Add `Paths_setdown` import and `other-modules` entry | Source of truth for the version string |
| Replace `summary` with a short version banner; move existing text to `details` | `app/Main.hs` |
| Regenerate `man/setdown.1` if it's derived from `--help`/`--version` output | Check `scripts/` for how the man page is built |
| Add a test asserting `--version` output contains the current version | `test/` — golden or unit, whichever matches the existing suite for CLI-level checks |
| Verify `--help` still reads sensibly with the description moved to `details` | Manual check — `cmdargs` renders `details` after the flag table |

## Open questions

- Whether `--version` should print just `setdown 0.2.1.0` or something closer to common CLI
  convention (`setdown 0.2.1.0, (C) 2015 Robert Massaioli`) — cosmetic, low stakes either way.
- Whether the four-part PVP version (`0.2.1.0`) is what should be user-facing, or whether it's
  worth trimming trailing zero components for display (`0.2.1`) — `showVersion` prints the
  Cabal-declared version verbatim, so this needs a deliberate choice, not just plumbing.
